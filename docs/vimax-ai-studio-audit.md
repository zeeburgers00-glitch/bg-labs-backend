# ViMax AI Studio — existing-project audit and release gates

Audit: 2026-10-28. This is an incremental audit of the existing `vimax-vert.vercel.app` project and the checked-out ViMax overlay, not a replacement application. The safe Git checkpoint before this work is `e6577e3aff697d917f6c8e7af59ef741a213b2fa` on the existing Arena branch. Do not merge an unrelated project, change shared Supabase authentication, discard existing data or rotate a production encryption key without a separate impact review.

## Architecture and evidence

- **Frontend:** the default hosted screen is the responsive JavaScript/HTML/CSS chat overlay in `frontend/chat/`. The pinned upstream ViMax frontend is built by `scripts/build.mjs`, overlaid, and retained with the older tools interface. `web/build.mjs` creates the actual Vercel output; `vercel.json` and `web/vercel.json` preserve existing routing.
- **Backend:** `web/api/bridge.mjs` delegates to the canonical Node handler in `api/bridge.mjs`; `api/providers.mjs`, `api/youtube.mjs`, `api/social.mjs`, `api/gpu.mjs`, `api/workforce-skills.mjs`, `api/creator-agents.mjs` and `api/youtube-public-research.mjs` implement bounded routes. The upstream Python companion under `skills/` runs separately and is not a cloud worker.
- **Authentication and database:** Supabase Auth and the existing shared Supabase database are retained. The handler uses HTTP-only cookies, user JWTs, origin checks and owner-scoped policies rather than a browser-visible service-role key. The existing migration history is in `supabase/migrations/`; no migration is required by this audit. The Supabase project is shared: unrelated tables and policies must not be silently altered.
- **Deployment:** Vercel project `vimax` builds from this repository's `web/` root. The earlier checkpoint was `e6577e3`. On 2026-10-28, incremental code commit `2fb50a9ddca713c5344da6a7454cda8179484c40` was deployed as `dpl_6NCSZJhTJHqG5n4Nr4JzRR1bBVVv` (READY/PROMOTED). An unauthenticated production health request reported `database: connected`, `text_chat: configured_unverified`, `video_agent: unavailable`, `gpu_preview: unconfigured` and `youtube_upload: configured_unverified`. The Google app sign-in status reported `enabled: false`; new agent and public-sample routes required sign-in. Configuration checks and unauthenticated requests are not end-to-end authentication, provider or upload tests.
- **Secrets:** server environment names are listed in `.env.example`; values must be configured privately as Vercel Sensitive variables and must not be sent to browser code, logs or Git. A production Groq variable exists, but its validity, rotation and inference are unverified. User-supplied keys exposed in chat must be considered compromised and privately rotated/revoked. Do not overwrite the independent YouTube token-encryption key merely to repair configuration; doing so makes saved grants unreadable.

## Incremental implementation and draft

- `api/creator-skills.mjs`, `api/workforce-skills.mjs`, `api/creator-agents.mjs` and the chat Creator tools dialog add fixed read-only checks, schemas, status and the composed draft review. The role browser does not start processes. `api/youtube-public-research.mjs` adds a separate optional official metadata sample, gated by authentication, account allowlist, quota confirmation and the shared attempt budget; it is default-off and only mocked in this assessment; no deployment configuration was set for it.
- Chat settings display provider **configuration** separately from an optional, user-confirmed live test of a selected model. A configured key alone is not verification; a successful response is a point-in-time result only. See [`ai-provider-setup.md`](ai-provider-setup.md) for the compatibility fixes, privacy, costs and remaining live-test requirement. Hacker AI has no adapter because its customer-specific endpoint was not independently verified. Existing `/skills/full.html` is linked for channel profiles, text-only mission control and manual private upload; neither starts a worker or enables an upload by itself.
- A one-off original morning-prayer draft was rendered outside the app using a selected AI voice, three AI-generated stills, FFmpeg and approximately timed burned-in captions. It is 5:35, 1280×720, H.264/AAC, with a separate SRT and thumbnail. It is not an online video backend and is not proof of a live GPU or YouTube integration. Captions need timing review, and the applicable AI-service usage rights must be confirmed before commercial use. There is no music and no verified competitor video template. The owner has not authorized a channel or approved publishing; no upload occurred.
- The nine private Drive videos have not been incorporated. The text extractor rejected the smallest MP4 at its 25 MB limit; the download connector saved two videos within its 100 MiB cap to excluded temporary storage, while seven exceed it. One inspected short file explicitly claimed the course was leaked; treat that as an unverified rights warning, not permission to reuse it. A 60-second sample of one lesson was attempted locally with a third-party packaged Whisper-small int8 model and `faster-whisper`; language confidence was low and output was garbled, so it is not a usable transcript and was not added to the app. Temporary course copies, sample and model were removed afterward; the Drive originals were not modified. A secure streaming/transcription worker, reliable transcription, retention controls and confirmed rights remain needed. No model-weight training took place.

## Incremental release gates

1. Keep existing routes, sessions, branding and data; re-run tests and do not add a migration unless its shared-project impact and rollback are documented.
2. Integrate only bounded, permission-scoped checks and reusable workflows whose real input/output, errors and tests can be demonstrated. Clearly label planned roles and uninstalled tools; do not send 100 model calls or invent running agents.
3. Before ingestion, establish course rights, transcription resources, private storage, provenance and deletion controls. A document index is not model-weight training. Never publish course material or treat its instructions as trusted system commands.
4. The requested competitor's exact public About page identified a Christian morning-prayer and devotional niche; its video list did not load in this environment. Visual style, narration, exact scripts, thumbnails, duration and performance were not verified. Do not reuse copyrighted clips, narration or scripts without permission, conflate similarly named channels, or invent template details.
5. Before a video job, agree on a compute/stock/voice estimate and durable worker/storage. Track source rights and artifacts. Do not start a paid service without approval.
6. Before any upload, obtain the actual channel's separate OAuth consent; show the final file, channel, title, description, privacy and cost. Publishing/scheduling requires an additional explicit owner approval. Never report an ambiguous or unverified provider response as successful.

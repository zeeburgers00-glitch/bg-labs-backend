# Read-only YouTube Analytics in chat

This optional adapter sends a fixed, user-initiated request to the official YouTube Analytics API for the **currently selected, authorized channel**. In chat, for example, type `show my channel analytics` or `analytics ka screenshot bhej do`. The result is a downloadable **ViMax visualization**, not a screenshot of YouTube Studio. It contains daily views, estimated watch minutes and subscribers gained for up to the last 30 calendar days ending yesterday. YouTube reports may be delayed; the requested range and latest reported day are shown, missing days are not estimated, and an empty report produces no image. It is not real-time analytics and does not contain revenue.

The chart and report stay in browser memory for that session and are not saved to chat history; save the image to keep it. Sign-out removes it from the page. No metrics or tokens are stored in the new budget tables. General AI chat still needs its own provider, though this fixed analytics request does not use an AI model. A configured flag is not proof of Google API availability, permission, or valid data.

## Setup (off by default)

1. Complete [Google app sign-in setup](google-signin.md) and the separate [YouTube channel setup](youtube-upload.md), protecting existing accounts and using the rotated secrets only in their private server settings. A channel connected with the previous upload-only grant remains usable for uploads; it is not silently given analytics access.
2. Enable **YouTube Analytics API** for the Google Cloud project of the YouTube OAuth client. Add the `https://www.googleapis.com/auth/yt-analytics.readonly` scope to its OAuth consent screen and complete Google test-user/verification requirements as applicable. The report also requires `youtube.readonly`. Each channel owner must grant the additional scope through Google; app login alone is insufficient. Do not paste credentials in chat or commit them.
3. Install the additive ViMax-only migration `202610280010_vimax_youtube_analytics.sql` through the project's approved migration process. It creates separate RLS-protected budget tables and a security-definer reservation function; it does not alter existing tables or store reports.
4. Set `VIMAX_YOUTUBE_ANALYTICS_ENABLED=true` in the ViMax Vercel production environment and redeploy. Once enabled, a new **Add channel with Google** authorization asks for Analytics as well as the existing channel/upload scopes. Google displays the permissions and the user may decline Analytics while still connecting the base channel. Reconnect an existing channel and grant Analytics to use reports for it. Recheck the actual selected channel; Google account and channel selection are separate from ViMax login.
5. Ask in chat for analytics and verify the reported channel and dates. If Google rejects access, check the channel, scope grant, API activation, verification status and quota; ViMax does not treat a syntax-valid config as a successful live connection.

Safety defaults: at most five Analytics requests per account and 20 for the deployment per UTC day, reserved atomically before the API request. Attempts, including failures and timeouts, count; these are attempt limits, not a financial cap or a Google quota guarantee. Authorization, owner/channel isolation, bounded results, empty data, error handling and PNG rendering have only been tested with simulated Google/Supabase services and isolated databases. A real Google grant, real report and Google Cloud OAuth review have not been verified.

Reference: [YouTube Analytics reports.query](https://developers.google.com/youtube/analytics/reference/reports/query) and [channel reports](https://developers.google.com/youtube/analytics/channel_reports).

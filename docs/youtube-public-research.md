# Optional public YouTube channel sample

This is a **read-only public metadata sample**, not an agent that watches a competitor's videos. It is separate from YouTube channel OAuth, Analytics and upload. It is **off by default** and has only been tested with mocked Google and Supabase responses; no real public lookup has been verified.

## Setup

1. In a Google Cloud project you control, enable the YouTube Data API v3. Create a separate restricted API key and restrict it to that API; review Google Cloud's key restriction guidance for your deployment's server egress. Do not use a browser-referrer-only restriction for a server-side key. Review project quotas, billing, YouTube API terms and any applicable privacy requirements.
2. Store the **new, unexposed** key privately as the Vercel Sensitive environment variable `YOUTUBE_PUBLIC_DATA_API_KEY`. Set `VIMAX_YOUTUBE_PUBLIC_RESEARCH_ENABLED=true` only when you intend to enable this feature, then redeploy. Never paste a key into chat, source files, browser code or logs. Keys previously shared in chat should be revoked/rotated; do not reuse those values.
3. Access uses the existing `VIMAX_AI_ALLOWED_USER_IDS` / `VIMAX_AI_ALLOW_ALL_AUTHENTICATED` gate, same-origin check and account-level provider pause. Sign in, open **Creator tools → Public channel sample**, supply an HTTPS YouTube handle or channel ID URL, and confirm the quota notice. The parser currently accepts ASCII handles only and does not support `/user/`, `/c/`, arbitrary URLs or unverified identity resolution.
4. Test with a known public channel only after the owner approves the usage. A syntactically configured key does not mean the lookup will succeed. Failure messages are sanitized; investigate project restrictions and quota privately. Disabling the flag stops new requests but not one already in flight.

## Quota, results and boundaries

- One approved sample reserves **one shared ViMax attempt** from the existing account/global daily budget; it appears as `feature=stock_search, provider=youtube` in the current ledger because the existing schema groups external public lookups under `stock_search`. The daily limits are shared with chat, Pexels and public GitHub lookups; they are not dollar spending caps.
- It makes at most three fixed-host Google requests: [`channels.list`](https://developers.google.com/youtube/v3/docs/channels/list), [`playlistItems.list`](https://developers.google.com/youtube/v3/docs/playlistItems/list) and, if there are video IDs, [`videos.list`](https://developers.google.com/youtube/v3/docs/videos/list). Google documents **one quota unit per request** as of 2026-10-28. Failed requests may also consume quota. There is no pagination or automatic retry; verify current terms and quotas in Google Cloud before enabling.
- The result contains a channel's public title, bounded description, visible counts and up to ten recent public videos with titles, published dates, durations and visible counts. Hidden/unavailable values are shown as unavailable, not inferred. These counts can be rounded or delayed. Only videos returned for the resolved channel and marked public are included; omitted/unavailable videos do not constitute a complete history.
- No audio, video, captions, full script, thumbnail imagery, visual template, private Analytics or channel ownership is verified. It does not promise performance, train a model, save the sample to the database, access private channels or publish. Public metadata is untrusted content and is rendered as text. UI results and confirmation are cleared on sign-out; the shared attempt ledger records the feature, provider and outcome, not the channel contents or key.
- Server requests use a fixed Google API host and place the API key in a server-side header, not a user-supplied URL. Requests have strict input and response bounds, timeouts and sanitized errors. The implementation does not change database schema or credentials. A separate security review and live end-to-end test remain necessary before relying on it.
